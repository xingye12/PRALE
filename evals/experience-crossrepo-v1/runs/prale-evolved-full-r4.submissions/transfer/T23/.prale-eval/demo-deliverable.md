## 1. Contract being demonstrated

`aider/repomap.py` implements the rendering layer of aider's repo map. The discovery
layer lives in `aider/repo.py`:

* `GitRepo.get_tracked_files` (aider/repo.py:433-488) returns repo-relative filenames from
  the commit tree + index, minus anything `ignored_file()` rejects.
* `GitRepo.ignored_file_raw` (aider/repo.py:542-565) applies `.aiderignore` through
  `pathspec.PathSpec.from_lines(pathspec.patterns.GitWildMatchPattern, ...)`.

`RepoMap` in `aider/repomap.py` never discovers files:

* `RepoMap.get_repo_map` (103-167) returns early on empty input and forwards the
  caller-supplied lists to `get_ranked_tags_map`.
* `RepoMap.get_ranked_tags` (365-574) scans only `chat_fnames ∪ other_fnames`, skipping
  paths where `Path(fname).is_file()` is false.
* `RepoMap.to_tree` (748-784) emits `<rel-fname>:` sections keyed by `tag.rel_fname`, so
  **map keys ⊆ supplied file list**.
* `RepoMap.get_tags_raw` (279-363) extracts the per-file `def`/`ref` tags that put a symbol
  into the map.
* The module's only `os.walk` lives in `find_src_files` (787-795) and is called only from
  the `if __name__ == "__main__":` debug block (852-861).

## 3. Normalized operation (why it is a normalization)

`aider.repomap` cannot be imported here: `diskcache`, `grep_ast` and `tree_sitter` are not
installed, and `aider.repo` needs `gitpython`; installing dependencies is out of scope for
this task. Installed and used instead: `pathspec 1.1.1`, the `git 2.43.0` CLI, stdlib `ast`.

| Production operation | Demo normalization |
| --- | --- |
| `GitRepo.get_tracked_files` (commit tree + index, minus ignored) | `git ls-files --cached` |
| `GitRepo.git_ignored_file` | `git check-ignore --quiet` |
| `GitRepo.ignored_file_raw` (pathspec over `.aiderignore`) | same `pathspec` + `GitWildMatchPattern` construction |
| `RepoMap.get_tags_raw` (tree-sitter per-file tags) | stdlib `ast` top-level def/class extraction, same per-file shape |
| `RepoMap.to_tree` rendering | `render_code_map()` emitting `<rel-fname>:` + definition lines |

The normalization keeps the two properties the proof depends on: discovery filters ignore
rules *before* the map is built, and the renderer consumes *only* the file list it is given.

## 5. Conclusion

The miniature repository demonstrates both halves of the acceptance condition on real
executed artifacts: ignored/generated files that physically exist on disk
(`build/generated_report.py`, the `.pyc` bytecode, plus the `.aiderignore`-excluded
`src/scratch_notes.py`) are absent from both the discovered file list and the rendered
code-map, while the relevant symbol `compute_invoice_total` is present under
`src/billing.py`. The map-key ⊆ discovered-file-list invariant and the `__main__`-only
`os.walk` check confirm the discovery/rendering layering of `aider/repomap.py`.

**Recorded limitation:** the real tree-sitter/`diskcache`/`gitpython` code path could not be
executed because those optional dependencies are unavailable and must not be installed;
the demo uses the documented normalization above and asserts the layering invariant
statically. No filesystem scanning, no dependency installation, and no changes outside
`.prale-eval/` were made.
